接入 · Anthropic 兼容Connect via the Anthropic-compatible API

完整实现 /v1/messages，含 streaming 与 tool use，官方 Anthropic SDK 直接指过来。/v1/messages is fully implemented — streaming and tool use included. Point the official SDK at it.

from anthropic import Anthropic

client = Anthropic(
    base_url="https://api.gonkarouter.io",   # no /v1 — the SDK appends /v1/messages
    api_key="sk-xxxxxx",
)

msg = client.messages.create(
    model="moonshotai/Kimi-K2.6",
    max_tokens=1024,                         # >= 1024, leave room for reasoning tokens
    messages=[{"role": "user", "content": "Reply with just: pong"}],
)

text = next((b.text for b in msg.content if getattr(b, "text", None)), "")
print(text)          # -> pong

Live Demo

开发一个简单的 DemoA minimal streaming app skeleton

from openai import OpenAI

client = OpenAI(
    api_key="sk-xxxxxx",
    base_url="https://api.gonkarouter.io/v1",
)

def ask(question: str, model="deepseek-ai/DeepSeek-V4-Flash-0731"):
    stream = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": question}],
        stream=True,                      # streaming feels far better in a demo
    )
    for chunk in stream:
        print(chunk.choices[0].delta.content or "", end="", flush=True)

ask("Summarise this week's support tickets and list the top 3 recurring issues.")

流式返回体验更好；同一个问题换 model= 跑三个模型，挑最适合你场景的那个。Streaming feels better in a demo — swap the model argument to run the same prompt through all three.

WorkBuddy 避坑 · Gotchas

四个会让你卡住的地方Four things that will bite you

404 基本都是 URLA 404 is almost always the URL

404 page not found 说明请求到了我们这儿、但路径不对。Key 错返回 401，模型名错返回 400 —— 都不长成 404。A bad key returns 401, an unknown model returns 400 — neither looks like this.

输出上限 4096Output caps at 4096 tokens

长回答会以 MAX_TOKENS 截断；不填 max_tokens 默认更低，只有 3072；填超过 4096 会被静默压回，客户端抬不高。Omitting max_tokens gives an even lower 3072, and asking for more is silently clamped back down.

模型 id 分目录Model ids differ per plan

带厂商前缀的 MiniMaxAI/MiniMax-M2.7 和短 id kimi-k2.6 属于不同目录，以你的 Key 在 /models 上看到的为准。Copy whatever the Models page shows for your own key.

请求经 WorkBuddy 中转Relayed by WorkBuddy's own backend

调用不是从你机器直连，而是走 WorkBuddy 的 SaaS 层，所以报错会带两个 id。找支持时，把报错卡片上的 Trace ID 一起给。That's why its errors carry two ids — quote the Trace ID when asking for help.

最佳实践 & 避坑Best practices, and the gotchas

✅ 该做的Do this

  • max_tokens ≥ 1024，给推理 token 留足空间Leave room for reasoning tokens
  • 模型 id 照抄 /models 页，大小写与斜杠精确Copy model ids verbatim from /models
  • 遇 429 退避 30–60s 重试（不扣费）On 429, back off 30–60s — it costs you nothing
  • 用 streaming 提升长回答的体验Stream long answers

⚠️ 生产限制（已验证）Verified production limits

  • 突发 ≥ 200 并发，稳态 ≤ 1000 req/min≥200 concurrent burst; ≤1000 req/min sustained
  • 持续 > 1500 req/min 开始返回 429Beyond 1500 req/min you'll see 429s
  • 单请求硬上限 10 分钟；空闲 90 秒断流10-minute hard cap per request; 90s idle closes the stream
  • 网关暂不支持 Anthropic prompt-caching，客户端关掉即可Prompt-caching headers aren't supported yet — disable them client-side

口诀：curl 先通 → SDK 改 base_url → 精确 model id → 429 退避重试。curl first → change the base URL → exact model id → back off on 429.
