## PART 1 — What the research changed about the idea

### 1.1 The receipts endpoint is your winning feature (most teams will miss this)

GonkaRouter returns an `X-Request-Id` header on every call, and there is a **public, unauthenticated** verification endpoint:

```
GET https://api.gonkarouter.io/v1/receipts/{x-request-id}
```

It returns model, timestamp, token usage and outcome — **without an API key**. That means a judge can independently confirm your inference really ran on the Gonka network.

**So: render every Request ID in the UI as a clickable link to its receipt.** On stage, say: *"Don't take our word for it — open this in your own browser right now."* The Gonka brief literally asks you to "prove the Truth wasn't generated by a centralized server." Almost nobody will actually wire the verification link. Do it — it costs 20 minutes.

### 1.2 Give the three models different JOBS and different INPUTS

Running the same prompt through three models and averaging is redundancy, not consensus, and a judge will see through it. Instead, give each model an **independent evidence base**:

| Model | Sees | Job |
|---|---|---|
| **DeepSeek-V4-Flash** | the message text ONLY | Classify the scam pattern. Knows nothing about the money. |
| **Kimi-K2.6** | the transaction context ONLY (recipient age, amount vs. normal, velocity, time) | Judge financial anomaly. Never sees the message. |
| **MiniMax-M2.7** | both verdicts + both inputs | Adjudicate, resolve conflict, narrate in the user's language. |

Now agreement is *meaningful* — two witnesses who cannot see each other's evidence reached the same conclusion. And it gives you a real answer to the "how do you handle disagreement?" question that Gonka's own docs call a major plus.

It also has a privacy dividend worth saying out loud: **the model that sees the money never sees the message, and the model that sees the message never sees the money.**

### 1.3 This answers the open Concern in your doc

> *"For Seniority Mode, who has the final authority?"*

Clean answer, and it's a strong pitch moment:

- **The AI never has authority.** It only produces a score. Authority lives in the Move contract.
- **The guardian can block instantly, but can never move, redirect, or seize funds.**
- **The elder always has the final word — but only after time passes.** Once the cooling-off window expires, the elder can push the transfer through over the guardian's objection.

That shape defeats scammers (who need speed) without enabling family financial abuse (which needs control). Say this in the Q&A and it will land.

### 1.4 The AI raises sensitivity; the contract provides the floor

Models are non-deterministic. A live demo where the judge types an obvious scam and your system says "looks fine" is fatal. Defend it three ways:

1. `temperature: 0` on all calls.
2. A **deterministic rules layer** that runs first — urgency keywords + bank account number + first-time recipient hard-flags to at least 70 regardless of what the models say.
3. The **chain rule is the real safety net** — a large transfer to a first-time recipient is blocked by the Move contract even if all three models fail.

This is honest engineering *and* a good line: *"the AI makes it smarter; the contract makes it safe."*

### 1.5 Cost is the argument for always-on protection

At roughly $0.0012 per 1M tokens with input and output priced the same, a ~500-token scam check costs a fraction of a sen. That's the reason protection can run on **every** transaction rather than only when someone asks — an argument you cannot make with a frontier API. Verify the current rate yourself before quoting it; Gonka's pricing adjusts with network utilisation.

### 1.6 Mirror Gonka's own vocabulary

Their brief describes a fact-checker with a **Truth Score (0–100)**, a **reasoning trace**, and **Request IDs**. Use the same words: call your output a **Scam Score (0–100)** with a **reasoning trace**. Frame the product as *"a fact-checker for the story someone is telling your grandmother."* Same build, mapped directly onto their scoring sheet.

### 1.7 Optional stretch: Kimi has vision

Kimi-K2.6 lists Vision. Fake bank SMS screenshots and forged payment receipts are a huge Malaysian scam vector. "Upload the screenshot they sent you" is a strong extra demo beat — only build it if the core flow is done by Thursday.

## PART 2 — Interface contract (lock this with your teammate today)

```ts
export interface RiskVerdict {
  riskScore: number;              // 0-100
  verdict: "ALLOW" | "REVIEW" | "BLOCK";
  scamType: string;               // e.g. "police_impersonation" | "none"
  explanation: string;            // English, one sentence
  explanationLocalised: string;   // ms / zh / ta
  modelsAgreed: boolean;
  disagreementNote?: string;      // shown to user when models split
  reasoningTrace: TraceStep[];
  redactedInput: string;          // exactly what was sent to the network
  latencyMs: number;
}

export interface TraceStep {
  role: "message_analyst" | "transaction_analyst" | "adjudicator";
  model: string;
  finding: string;
  gonkaRequestId: string;
  receiptUrl: string;             // https://api.gonkarouter.io/v1/receipts/<id>
}
```

**Sui side reads `verdict` and `riskScore` only.** Everything else is for the UI. Your teammate can hardcode `{riskScore: 87, verdict: "BLOCK"}` from hour one and never wait for you.

### 3.1 `src/gonka.ts` — client that captures the Request ID

```ts
const BASE = "https://api.gonkarouter.io/v1";

export const MODELS = {
  message:     "deepseek-v4-flash-0731", // verify with the ping above
  transaction: "kimi-k2-6",
  adjudicator: "minimax-m2-7",
} as const;

export interface GonkaCall { text: string; requestId: string; receiptUrl: string; }

export async function callGonka(
  model: string, system: string, user: string, maxTokens = 500,
): Promise<GonkaCall> {
  const res = await fetch(`${BASE}/chat/completions`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${process.env.GONKA_API_KEY}`,
      "content-type": "application/json",
    },
    body: JSON.stringify({
      model,
      max_tokens: maxTokens,
      temperature: 0,                       // determinism matters for a live demo
      response_format: { type: "json_object" },
      messages: [
        { role: "system", content: system },
        { role: "user", content: user },
      ],
    }),
  });

  if (!res.ok) throw new Error(`Gonka ${model} ${res.status}: ${await res.text()}`);

  // The proof-of-decentralised-inference lives in this header. Never drop it.
  const requestId = res.headers.get("x-request-id") ?? "unknown";
  const json: any = await res.json();

  return {
    text: json.choices?.[0]?.message?.content ?? "",
    requestId,
    receiptUrl: `${BASE}/receipts/${requestId}`,
  };
}
```

### 3.2 `src/redact.ts` — strip PII before it leaves the device

```ts
export function redact(input: string): string {
  return input
    .replace(/\b\d{6}-\d{2}-\d{4}\b/g, "[IC]")            // Malaysian IC
    .replace(/\b(?:\+?60|0)1\d[-\s]?\d{3,4}[-\s]?\d{4}\b/g, "[PHONE]")
    .replace(/\b\d{10,16}\b/g, "[ACCOUNT]")
    .replace(/\b[\w.+-]+@[\w-]+\.[\w.]+\b/g, "[EMAIL]");
}
```

Show `redactedInput` in the UI. That single panel is your entire answer to the privacy question — and it replaces the TEE you cut.

### 3.3 `src/rules.ts` — the deterministic floor

```ts
const URGENCY = [
  "immediately","sekarang juga","segera","马上","立刻","urgent","within the hour",
  "account will be frozen","akaun akan dibekukan","冻结","arrest","tangkap","逮捕",
  "do not tell","jangan beritahu","别告诉","court order","saman","传票",
];
const AUTHORITY = ["pdrm","police","polis","警察","lhdn","bank negara","court","mahkamah","法院","nsrc"];

export function ruleFloor(msg: string) {
  const m = msg.toLowerCase();
  const urgency   = URGENCY.filter(k => m.includes(k)).length;
  const authority = AUTHORITY.filter(k => m.includes(k)).length;
  const hits: string[] = [];
  if (urgency)   hits.push(`${urgency} urgency phrase(s)`);
  if (authority) hits.push(`claims authority`);
  // classic Macau scam signature: impersonated authority + time pressure
  const floor = urgency && authority ? 70 : urgency || authority ? 40 : 0;
  return { floor, hits };
}
```

### 3.4 `src/committee.ts` — the three-role committee

```ts
import { callGonka, MODELS, GonkaCall } from "./gonka";
import { redact } from "./redact";
import { ruleFloor } from "./rules";

export interface TxContext {
  amountMYR: number;
  recipientIsNew: boolean;
  usualMaxMYR: number;
  transfersLastHour: number;
  localHour: number;
}

const J = (c: GonkaCall) => { try { return JSON.parse(c.text); } catch { return {}; } };

export async function runCommittee(
  rawMessage: string, tx: TxContext, lang: "en" | "ms" | "zh" = "en",
) {
  const t0 = Date.now();
  const message = redact(rawMessage);
  const { floor, hits } = ruleFloor(message);

  // Two independent witnesses, run in PARALLEL so the demo isn't dead air.
  const [msgCall, txCall] = await Promise.all([
    callGonka(MODELS.message,
      `You detect scams targeting elderly Malaysians. Common patterns: police/LHDN/court
impersonation (Macau scam), parcel scam, love scam, fake investment, fake loan approval.
You see ONLY a message — you know nothing about any payment.
Reply JSON: {"score":0-100,"scamType":string,"evidence":[string]}`,
      `Message:\n"""${message}"""`),

    callGonka(MODELS.transaction,
      `You detect anomalous money transfers by elderly users.
You see ONLY transfer metadata — you never see any message.
Reply JSON: {"score":0-100,"anomalies":[string]}`,
      JSON.stringify(tx)),
  ]);

  const msgV = J(msgCall), txV = J(txCall);

  // Adjudicator is the only one that sees both.
  const adjCall = await callGonka(MODELS.adjudicator,
    `You are the adjudicator protecting an elderly user's wallet. Two independent analysts
reviewed separate evidence. Be conservative: when they disagree, lean toward protecting the user.
Reply JSON: {"riskScore":0-100,"verdict":"ALLOW"|"REVIEW"|"BLOCK","scamType":string,
"explanation":"one plain sentence, no jargon","explanationLocalised":"same sentence in ${lang}"}`,
    JSON.stringify({ messageAnalyst: msgV, transactionAnalyst: txV, deterministicHits: hits }));

  const adj = J(adjCall);

  // Deterministic floor can only ever RAISE risk — models can't talk it down.
  const riskScore = Math.max(adj.riskScore ?? 0, floor);
  const verdict = riskScore >= 70 ? "BLOCK" : riskScore >= 40 ? "REVIEW" : "ALLOW";
  const agreed = Math.abs((msgV.score ?? 0) - (txV.score ?? 0)) <= 30;

  const step = (role: any, model: string, finding: string, c: GonkaCall) =>
    ({ role, model, finding, gonkaRequestId: c.requestId, receiptUrl: c.receiptUrl });

  return {
    riskScore,
    verdict,
    scamType: adj.scamType ?? msgV.scamType ?? "none",
    explanation: adj.explanation ?? "",
    explanationLocalised: adj.explanationLocalised ?? adj.explanation ?? "",
    modelsAgreed: agreed,
    disagreementNote: agreed ? undefined
      : `Analysts disagreed (message ${msgV.score}, transaction ${txV.score}) — treated as higher risk.`,
    reasoningTrace: [
      step("message_analyst",     MODELS.message,     (msgV.evidence ?? []).join("; "), msgCall),
      step("transaction_analyst", MODELS.transaction, (txV.anomalies ?? []).join("; "), txCall),
      step("adjudicator",         MODELS.adjudicator, adj.explanation ?? "",            adjCall),
    ],
    redactedInput: message,
    latencyMs: Date.now() - t0,
  };
}
```
